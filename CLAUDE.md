# tui-canvas

Persistent canvas display panel for Claude Code sessions. A Go binary that is simultaneously a TUI client, a background daemon, and a Claude Code plugin.

See [ARCHITECTURE.md](ARCHITECTURE.md) for a full explanation of the three-part system.

## Keeping Docs Current

When making changes to this codebase, update `CLAUDE.md` and `ARCHITECTURE.md` in the same commit:
- New subcommands → update Repository Layout, Common Tasks, and the protocol tables in ARCHITECTURE.md
- New keybindings → update the keybindings table in ARCHITECTURE.md
- Skill changes → update the Skills section in ARCHITECTURE.md
- Protocol changes → update the Protocol Reference tables in ARCHITECTURE.md

## Build & Install

```bash
make build    # produces ./tui-canvas binary
make install  # builds + installs to ~/.local/bin/tui-canvas
make test     # go test ./...
make clean    # removes ./tui-canvas
```

Always use `make build` / `make install` rather than calling `go build` directly.

After `make install`, the running daemon must be restarted to pick up binary changes. Press `R` in the TUI or run `tui-canvas restart` — connected TUIs reconnect automatically.

## Repository Layout

```
cmd/tui-canvas/main.go       entry point; subcommand dispatch
internal/
  daemon/daemon.go            background state server
  protocol/protocol.go        shared message types + socket path
  tui/
    model.go                  bubbletea model + update logic
    view.go                   rendering (tab bar, viewport, help bar)
plugin/
  .claude-plugin/plugin.json  plugin manifest
  hooks/
    hooks.json                SessionStart + Stop hook declarations
    session-start             bash script: registers session, writes session-$ID temp file
    stop-push                 bash script: reads staging file, appends to canvas after each turn
  skills/
    tui-canvas/SKILL.md       /tui-canvas skill (send content to canvas)
    tui-clear/SKILL.md        /tui-clear skill (clear canvas)
```

## Key Libraries

- **bubbletea** (`github.com/charmbracelet/bubbletea`) — TUI event loop and model
- **bubbles/viewport** (`github.com/charmbracelet/bubbles`) — scrollable content pane
- **glamour** (`github.com/charmbracelet/glamour`) — markdown → terminal rendering
- **lipgloss** (`github.com/charmbracelet/lipgloss`) — terminal styling

## Plugin State File

The daemon persists session registrations to `~/.local/share/tui-canvas/sessions.json` and reloads on startup. Do not edit this file manually.

## Common Tasks

**Finding the session ID after `/clear`:** run `tui-canvas list` — returns tab-separated `id name cwd` rows. Or press `?` in the TUI to toggle debug mode, which shows session IDs inline.

**Sending content to the canvas:**
```bash
tui-canvas append SESSION_ID <<'EOF'
markdown content here
EOF
```

**Clearing a session canvas:**
```bash
tui-canvas clear SESSION_ID
```

**Restarting the daemon** (required after `make install` to pick up binary changes):
```bash
tui-canvas restart   # TUIs reconnect automatically
# or press R inside the TUI
```

**Killing a tab:** press `x` in the TUI, then `x` again to confirm. Removes the session and all its canvas entries from persistent state.
